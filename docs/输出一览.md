# pty-agent 输出一览

> 列出所有可能的输出场景，JSON 格式（唯一输出模式）。

---

## 1. 输出模式

仅支持 **JSON 模式**：stdout 每行输出一个 JSON 对象。

---

## 2. 命令响应输出

### 2.1 exec / send / read — result 类型

守护进程返回 `commandType` 为 `exec` / `send` / `read` 的 result 响应。

#### PTY 模式（ConPTY/UnixPTY）— 单流输出

```json
{
  "commandType": "exec",
  "sessionId": "myid",
  "outputStream": "Python 3.11.9 ...\n>>> ",
  "outputOffset": 1234,
  "triggerReturnReason": "trigger_matched",
  "program": {
    "rawStartCommand": "python -i -u",
    "startTime": "2026-06-22T14:32:15.47",
    "nowTime": "2026-06-22T15:20:30.12",
    "running": true,
    "ptyType": "conpty",
    "exitCode": null,
    "errorMessage": null,
    "debugInformation": {
      "processes": [
        {"pid": 1234, "path": "C:\\Python311\\python.exe"}
      ],
      "guiWindows": [],
      "pendingEvents": [
        {
          "time": "2026-06-22T14:32:15.47",
          "type": "process_spawn",
          "pid": 1234,
          "detail": {"path": "C:\\Python311\\python.exe"}
        }
      ],
      "hint": "Events are consumed when exec/send/mouse commands return. Below are pending events captured at that time."
    }
  },
  "hint": "The program started successfully. It is now returning due to trigger match."
}
```

`--no-debug` 时移除 `debugInformation` 字段。

#### triggerReturnReason 值

| 值 | 含义 |
|---|---|
| `trigger_matched` | 正则表达式命中 |
| `trigger_timeout` | 触发等待超时 |
| `idle_timeout` | 输出静默超时 |
| `program_ended` | 程序结束 |
| `gui_detected` | 检测到 GUI 窗口 |
| `program_crashed` | 程序崩溃 |
| `ok` | 无触发条件，正常返回 |

#### snapshot-mode 会话输出

snapshot-mode 会话（`exec --snapshot-mode`）下，`exec`/`send`/`read` 返回的 `outputStream` 为终端屏幕快照文本（非原始 VT 序列）。

snapshot-mode 支持 `--trigger`（匹配快照文本）和 `--idle-timeout`（检测屏幕无变化），`triggerReturnReason` 根据实际返回原因变化：

| triggerReturnReason | 说明 |
|---|---|
| `ok` | 无 trigger/idle-timeout，正常等待 timeout 后返回 |
| `trigger_matched` | 快照文本匹配了 `--trigger` 正则 |
| `idle_timeout` | 屏幕在 `--idle-timeout` 秒内无变化 |
| `trigger_timeout` | 有 trigger 但未匹配，超时返回 |

```json
{
  "commandType": "send",
  "sessionId": "mimo",
  "outputStream": "  ┃  输入消息...(输入/唤起命令)\n  ┃  Build · MiMo Auto\n  ╹▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀▀",
  "outputOffset": 64105,
  "triggerReturnReason": "trigger_matched",
  "program": { "running": true, "ptyType": "win-conpty" }
}
```

若快照为空，响应附带 `snapshotDiagnostics` 字段（含 pyte 状态、feed 计数、display 行数等诊断信息）。

非 snapshot-mode 会话使用 `--snapshot` 参数（`read --snapshot` / `send --snapshot`）也可获取快照输出。`--snapshot` 对非 snapshot-mode 会话同样有效（守护进程会走快照流程并附带 screenBuffer）。

#### 快照差异（--snapshot-diff / -s）

`--snapshot-diff` 仅返回屏幕变化的行，需搭配快照模式（`--snapshot-mode` / `--snapshot`），且仅支持 stream 格式（与 `--response-format svg` 互斥）。

- 首次调用返回完整快照（无历史对比）
- 后续调用只返回变化的行，格式为 `行号:内容`（行号从0开始）
- 无变化时 `outputStream` 为空

```json
{"commandType":"send","sessionId":"myid","outputStream":"3:C:\\Users>echo hello\n4:hello\n6:C:\\Users>","triggerReturnReason":"ok"}
```

#### screenBuffer 传输优化

当客户端请求中包含 `include_screen_buffer: true`（`--output` 或 `--response-format svg` 时自动添加），响应中附带屏幕缓冲区数据：

- **`screenBufferZ`**：gzip 压缩 + base64 编码的屏幕缓冲区 JSON（稀疏格式）
- **`screenBufferMeta`**：元信息 `{"cols": N, "rows": N, "sparse": true, "compressed": true}`

客户端自动解压 `screenBufferZ` 为 `screenBuffer` 后供渲染器使用。

**稀疏格式**：仅传输非默认单元格（空格+default颜色+非粗体），每个单元格含 `c`（列号）、`d`（字符）、`f`（前景色）、`b`（背景色）、`bo`（粗体）字段。典型 80×24 终端从全量 94KB 压缩至 <1KB。

**指定 `--output` 时 stdout 精简**：`screenBuffer`/`screenBufferMeta` 不打印到 stdout，仅写入目标文件。

#### 渲染器

`--output` 指定图片文件时，渲染器将 screenBuffer 渲染为图片：

| 渲染路径 | 格式 | 依赖 | 说明 |
|---------|------|------|------|
| GDI + BuiltinGlyphs | PNG/JPG/BMP | Windows + Pillow | Windows 首选。对 U+2500-U+259F（Box Drawing + Block Elements）用 GDI `FillRect` 几何图元绘制，消除字体字形间隙。CJK 字符通过 `ExtTextOutW` 系统字体回退自动渲染 |
| SVG | SVG | 无 | 零依赖矢量图，字体依赖查看器 |
| Pillow 回退 | PNG/JPG/BMP | Pillow | GDI 失败时降级，TrueType 字体回退链 |
| 纯文本 | TXT/LOG | 无 | 直接写入 outputStream 内容（非 snapshot 模式下为原始 VT 序列去除 ANSI 后的文本，不是屏幕快照；如需快照文本请先用 `--snapshot` 获取） |

字符宽度计算优先使用 `wcwidth` 库（正确处理 CJK 双宽、零宽字符），回退到 `unicodedata.east_asian_width()`。

#### hint 文本

| 场景 | hint |
|---|---|
| exec + trigger_matched | "The program started successfully. It is now returning due to trigger match." |
| exec + trigger_timeout | "The program started successfully. Trigger wait timed out." |
| exec + idle_timeout | "The program started successfully. Output has been idle." |
| exec + program_ended | "The program started successfully but has now ended." |
| exec + gui_detected | "The program started successfully. A GUI window was detected." |
| exec + program_crashed | "Program crashed with exit code: {N}." |
| exec + ok | "The program started successfully." |
| send + trigger_matched | "Input sent successfully. It is now returning due to trigger match." |
| send + trigger_timeout | "Input sent successfully. Trigger wait timed out." |
| send + idle_timeout | "Input sent successfully. Output has been idle." |
| send + program_ended | "Input sent successfully. The program has now ended." |
| send + gui_detected | "Input sent successfully. A GUI window was detected." |
| send + program_crashed | "Program crashed with exit code: {N}." |
| send + ok | "Input sent successfully." |
| read + ok | "" |
| read + session ended | "Session ended (you are viewing data from an old session). Re-run exec to restart." |
| events + session ended | 同上 |
| events + has pending | "Listed below are unconsumed events; viewing marks them consumed. Enter a command to view recent events." |
| debugInformation + has pendingEvents | 同上 |

### 2.3 events — 事件查询

```json
{
  "commandType": "events",
  "sessionId": "myid",
  "pendingEvents": [
    {
      "time": "2026-06-22T14:32:15.47",
      "type": "process_spawn",
      "pid": 11888,
      "currentlyActive": false,
      "detail": {"path": "C:\\Python311\\python.exe"}
    },
    {
      "time": "2026-06-22T14:32:16.89",
      "type": "process_crash",
      "pid": 14708,
      "currentlyActive": false,
      "detail": {"exitCode": 1, "errorMessage": "STATUS_ACCESS_VIOLATION"}
    }
  ],
  "count": 2,
  "hint": "Listed below are unconsumed events; viewing marks them consumed. Enter a command to view recent events."
}
```

会话已结束时 hint 包含：
```
"Session ended (you are viewing data from an old session). Re-run exec to restart."
```

#### 事件 detail 字段

| 事件类型 | detail 内容 |
|---|---|
| `process_spawn` | `{"path": "C:\\...\\python.exe"}` |
| `process_exit` | `{"exitCode": 0}` |
| `process_crash` | `{"exitCode": 1, "errorMessage": "..."}` |
| `gui_window` | `{"title": "...", "className": "..."}` |

### 2.7 error 类型

所有错误响应格式统一：

```json
{"type": "error", "error": "会话 'xxx' 不存在"}
```

常见错误消息：

| 场景 | error 内容 |
|------|-----------|
| 会话不存在 | `Session 'xxx' not found` |
| 会话已结束 | `Session 'xxx' ended, kill and re-exec to restart` |
| 缺少会话 id | `Missing session id` |
| 缺少 command | `Missing command parameter` |
| 认证失败 | `Authentication failed` |
| 未知指令 | `Unknown command type: xxx` |
| JSON 解析失败 | `Invalid request: JSON parse failed` |
| 服务器内部错误 | `Internal server error` |
| 写入输入失败 | `Failed to write input` |
| 启动会话失败 | `Failed to start session: <异常信息>` |
| 参数过长 | `Parameter 'xxx' too long (max N chars)` |
| 无效正则 | `Invalid regex: xxx` |
| 无效行范围 | `Invalid line range: xxx` |
| 缺少 hwnd | `Missing hwnd parameter` |
| 关闭窗口失败 | `Failed to close window` |

## 3. 守护进程生命周期信息（info 类型）

由 `start_daemon()` / `stop_daemon()` 内部 `_safe_print()` 输出。

所有信息以 `{"type":"info","message":"..."}` 格式输出到 stdout：

| 场景 | message |
|------|---------|
| 守护进程已在运行 | `[pty-agent] Daemon already running (port 12345)` |
| 守护进程已启动 | `[pty-agent] Daemon started (port 12345)` |
| 可用 shell 信息 | `[pty-agent] Shells: cmd (...), powershell (...), pwsh (...), bash (unavailable)` |
| 守护进程启动失败（超时） | `[pty-agent] Daemon start failed (timeout), port 12345 may be occupied` |
| 守护进程未运行 | `[pty-agent] Daemon not running` |
| 停止守护进程失败 | `[pty-agent] Daemon stop failed (response: ...)` |
| TCP 停止失败 | `[pty-agent] TCP stop failed: <异常>` |
| 已强制终止 | `[pty-agent] Daemon force-killed (PID 12345)` |
| 强制终止失败 | `[pty-agent] Force kill failed: <异常>` |
| 守护进程已停止 | `[pty-agent] Daemon stopped` |
| 守护进程启动失败（异常） | `[pty-agent] Daemon start failed: <异常>` |

示例（`exec` 自动启动守护进程，stdout 逐行输出）：
```json
{"type":"info","message":"[pty-agent] Daemon started (port 54482)"}
{"type":"info","message":"[pty-agent] Shells: cmd (...), powershell (...)"}
{"commandType":"exec","sessionId":"py","outputStream":"Python 3.11.9 ...\n>>> ","outputOffset":0,"triggerReturnReason":"trigger_matched","program":{...}}
```

## 4. 非命令响应输出

以下输出不来自守护进程响应，由客户端 `__main__.py` 直接生成。

### 4.1 配置查询 — config 类型（`--show-config`）

```json
{"type": "config", "content": "当前调用配置:\n  always_return_snapshot = off\n  debug = on\n  encoding = (未设置)\n  keep_ansi = off\n  newline = off\n  send_eol = cr (\r)\n  timeout = 120.0\n  # 注: 这些默认值仅在有子命令（如 exec/send）时生效，仅作查询参考"}
```

### 4.2 帮助文本 — help 类型（无子命令）

```json
{"type": "help", "content": "usage: pty-agent [-h] [--show-config [KEY]] ...\n\n命令行交互式程序交互代理\n..."}
```

### 4.3 警告信息 — warning 类型

```json
{"type": "warning", "message": "警告: --default 仅在与子命令（如 exec/send）配合时有效，单独使用不会产生效果\n  已设置临时值: timeout = 30"}
```

### 4.4 客户端异常

```json
{"type": "error", "error": "操作被用户中断"}
```

### 4.5 客户端连接错误（transport.py）

以下错误输出到 **stderr**：

| 场景 | stderr 输出 |
|------|------------|
| 启动守护进程失败 | `error: failed to start daemon` |
| 重启守护进程失败 | `error: failed to restart daemon` |
| 连接失败 | `error: <异常信息>` |

### 4.6 守护进程无响应

```json
{"type": "error", "error": "daemon not responding"}
```

## 7. 响应格式（--response-format）

`exec`/`send`/`read` 支持 `--response-format <stream|svg>` 选择响应格式：

| 格式 | 说明 | 依赖 |
|------|------|------|
| `stream` | 默认，JSON 格式输出 | 无 |
| `svg` | 返回 SVG 矢量图（JSON 包装） | PTY 会话的屏幕缓冲区 |

`--response-format svg` 时，响应格式为 `{"type": "svg", "data": "<svg>...</svg>"}`。对有 ConPTY 的 session，`--response-format svg` 会自动通过 `include_screen_buffer` 请求屏幕缓冲区数据，无需显式 `--snapshot`。

注：`--response-format svg` 需要 PTY 会话的屏幕缓冲区（exec: `--snapshot-mode`; send/read: `--snapshot`; 或 `--default always-return-snapshot on`）

### SVG 压缩等级（--svg-compression-level）

| 等级 | 说明 | 依赖 |
|------|------|------|
| 0 | 不压缩，仅移除空标签 | 无 |
| 1 | 轻度压缩（保留换行缩进，digits=5） | scour |
| 2 | 深度压缩（strip prolog, shorten ids, digits=3，默认） | scour |

注：scour 未安装时自动降级为 level 0。安装: `pip install scour`

### 依赖关系

```
--response-format svg
    └── PTY 会话的屏幕缓冲区
            ├── exec: --snapshot-mode
            ├── send: --snapshot（非 snapshot-mode 会话也可用）
            ├── read: --snapshot（非 snapshot-mode 会话也可用）
            ├── --default always-return-snapshot on
            └── 自动通过 include_screen_buffer 请求（有 ConPTY 的 session）
```

## 8. JSON 输出类型汇总

| type / commandType | 来源 | 说明 |
|------|------|------|
| `exec` / `send` / `read` | 守护进程 result 响应 | 命令执行结果 |
| `list` | 守护进程 list 响应 | 会话列表 |
| `events` | 守护进程 events 响应 | 事件查询 |
| `kill` | 守护进程 kill 响应 | 终止会话 |
| `closewin` | 守护进程 closewin 响应 | 关闭 GUI 窗口 |
| `stop` | 守护进程 stop 响应 | 停止守护进程 |
| `error` | 守护进程 / 客户端 | 错误响应 |
| `info` | `lifecycle._safe_print()` | 守护进程启停信息 |
| `config` | `__main__.py` | `--show-config` 配置查询 |
| `help` | `__main__.py` | 无子命令时的帮助文本 |
| `warning` | `__main__.py` | 参数警告 |
| `pong` | 守护进程 | ping 响应（内部使用，不输出到 CLI） |
