## 2. 目标

搭建项目骨架，验证 CMake + 第三方库集成 + 命名管道最小握手链路。Phase 0 结束时，Python 端能启动沙箱、收到 Ready 事件、发送 Shutdown 优雅退出。

---

## 3. 范围

### In Scope
- CMake 工程结构（≥ 3.20）
- third_party 子模块：WIL、nlohmann_json、spdlog
- 目录结构（src/core、src/adapters、src/infra、python、tests、docs）
- main.cpp：命令行解析（`--pipe`、`--config`、`--log-level`）
- 日志系统初始化（spdlog，文件 + stderr）
- 最小命名管道服务端：
  - 创建管道（DACL 限制当前用户）
  - 接受连接
  - 发送 `Ready` 事件
  - 接收 `Shutdown` 命令并退出
- IPC 帧编解码（长度前缀 + JSON）
- Python 最小客户端：`win_sandbox.client.SandboxClient`
  - `start()`：subprocess 启动沙箱
  - `wait_ready()`：阻塞等 Ready
  - `shutdown()`：发送 Shutdown 并等退出
  - `close()`：清理

### Out of Scope
- Job Object 资源限制（Phase 1）
- AppContainer 隔离（Phase 2）
- StartProcess / 进程管理（Phase 1）
- 配置文件 schema 校验（Phase 1）
- 多客户端（Phase 3）

## 5. 任务清单

### T0.1 工程初始化
- 创建 `CMakeLists.txt`（顶层）
- 创建 `cmake/` 辅助脚本目录
- 初始化 git 仓库
- 添加 `.gitignore`（build/、*.log、__pycache__/ 等）
- 创建 `AGENTS.md` 已存在，无需修改

**验收**：`git status` 干净，目录结构符合 HLD §12.1。

### T0.2 第三方库集成
- `git submodule add https://github.com/microsoft/wil third_party/wil`
- `git submodule add https://github.com/nlohmann/json third_party/nlohmann_json`
- `git submodule add https://github.com/gabime/spdlog third_party/spdlog`
- 使用镜像源（参考 `.agents/skills/download-by-mirror`）
- CMake 配置 `add_subdirectory` 或 `FetchContent`

**验收**：CMake 配置成功，三个库的头文件可被 include。

### T0.3 核心层骨架
- `src/core/entities/`：空目录 + placeholder
- `src/core/usecases/`：空目录 + placeholder
- `src/core/ports/`：空目录 + placeholder
- `src/adapters/`：空目录 + placeholder
- `src/infra/`：子目录占位（job/、appcontainer/、process/、etw/、wfp/、fs/、ipc/、stats/、logging/、json/）

**验收**：目录结构存在，CMake 能编译空目标。

### T0.4 日志系统
- `src/infra/logging/Logger.hpp`：spdlog 封装
- `src/infra/logging/Logger.cpp`：初始化（文件按天滚动 + stderr）
- 级别：trace/debug/info/warn/error
- 日志路径：`%TEMP%\win-sandbox-<pid>\sandbox.log`

**验收**：`Logger::Init("info")` 后，`spdlog::info("test")` 同时输出到文件和 stderr。

### T0.5 IPC 帧编解码
- `src/infra/ipc/FrameCodec.hpp`：
  - `Encode(const IpcMessage&) -> bytes`
  - `Decode(bytes_view) -> Result<IpcMessage>`
- 帧格式：`[4字节小端长度][UTF-8 JSON]`
- 最大消息 16MB
- `IpcMessage` 结构：`type`、`request_id`、`payload`(JSON)

**验收**：单元测试覆盖 encode/decode 往返、超长消息拒绝、损坏帧检测。

### T0.6 命名管道服务端（最小）
- `src/infra/ipc/NamedPipeServerImpl.hpp/cpp`
- `CreateNamedPipeW`（PIPE_ACCESS_DUPLEX | FILE_FLAG_OVERLAPPED）
- DACL：仅当前用户 SID
- `ConnectNamedPipe`（OVERLAPPED 异步）
- 发送 `Ready` 事件
- 接收 `Shutdown` 命令 → 关闭管道 → 退出 main

**验收**：`sandbox.exe --pipe \\.\pipe\test` 启动后，Python 端能连接并收到 Ready；发送 Shutdown 后沙箱退出码 0。

### T0.7 main.cpp
- 解析命令行：`--pipe <name>`、`--config <path>`（可选）、`--log-level <level>`
- 初始化日志
- 创建 NamedPipeServer
- 发送 Ready
- 阻塞等待 Shutdown
- 退出

**验收**：命令行参数解析正确，未知参数报错。

### T0.8 Python 最小客户端
- `python/win_sandbox/__init__.py`
- `python/win_sandbox/client.py`：`SandboxClient` 类
  - `__init__(exe_path, pipe_name)`
  - `start()`：subprocess.Popen
  - `wait_ready(timeout)`：阻塞读 Ready
  - `send_shutdown()`：发 Shutdown 帧
  - `wait_exit(timeout)`：等进程退出
  - `close()`：清理资源
- `python/win_sandbox/protocol.py`：帧编解码（Python 端镜像 C++ 实现）
- `python/win_sandbox/exceptions.py`：`SandboxError`、`TimeoutError`、`ProtocolError`

**验收**：Python 脚本能完成 start → wait_ready → send_shutdown → wait_exit 全流程。

### T0.9 单元测试
- `tests/unit/test_frame_codec.cpp`：帧编解码往返
- `tests/unit/test_ipc_message.cpp`：IpcMessage 序列化
- 使用 GoogleTest 或 Catch2（推荐 GoogleTest，FetchContent 集成）
- CMake `enable_testing()` + `add_test`

**验收**：`ctest` 全绿。

### T0.10 e2e 冒烟测试
- `tests/e2e/test_smoke.py`：Python 启动沙箱 → 收 Ready → Shutdown → 退出
- 超时 10s
- 验证退出码 0

**验收**：`python tests/e2e/test_smoke.py` 退出码 0。

## 6. 风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| 第三方库镜像下载慢 | T0.2 阻塞 | 使用 download-by-mirror skill，配 ghproxy |
| spdlog 与 MSVC 版本不兼容 | 编译失败 | 锁定 spdlog 1.x 稳定版本 |
| 命名管道 DACL 配置错误 | 跨用户访问或拒绝访问 | 单测验证 DACL，参考 Windows SDK 示例 |
| Python 端帧编解码与 C++ 不一致 | 握手失败 | 共享一份 JSON schema 文档，双端对齐 |
