# LLD-04：IPC 模块（命名管道 + 协议）

## 1. 模块概述

| 项 | 内容 |
|----|------|
| 模块 | IPC（命名管道服务端 + 帧编解码 + 消息协议） |
| 路径 | `src/infra/ipc/`、`src/adapters/IpcMessageAdapter/` |
| 上游 | HLD §4.4（框架层）、§7.4（IIpcServer 接口） |
| 下游 | Phase 0（最小握手）、Phase 1（命令/事件）、Phase 3（完整协议） |
| 实现 Phase | Phase 0 启动，Phase 3 完整 |

### 职责
- 提供 Windows 命名管道服务端，接受 Python 客户端连接
- 帧编解码（长度前缀 + JSON）
- 消息序列化/反序列化（nlohmann::json）
- 多客户端管理（controller / observer）
- 事件广播与命令路由
- DACL 安全描述符

### 不职责
- 业务逻辑（用例层负责）
- Job/AppContainer 操作（各自模块负责）
- Python 端实现（Python 包负责，但协议双端对齐）

---

## 2. 详细设计目标

| 目标 | 指标 |
|------|------|
| 单向延迟 | ≤ 5ms（<4KB 消息，本机） |
| 吞吐 | ≥ 50000 events/s（小消息） |
| 最大消息 | 16MB（超出分片） |
| 并发客户端 | ≥ 8 |
| 错误恢复 | 客户端断连不崩溃，重连可恢复 |
| 安全 | 仅当前用户 SID 可连接 |

## 3. 数据模型

### 3.1 IPC 帧（Wire Format）

```
+----------------+-------------------+
| Length (4 byte)| Payload (UTF-8)   |
| little-endian  | JSON text         |
+----------------+-------------------+

Length: 不含自身 4 字节,范围 [0, 16777216] (16MB)
Payload: UTF-8 编码的 JSON 文本
```

- 长度 0：心跳帧（keepalive）
- 长度 > 16MB：非法，断开连接

### 3.2 IpcMessage 结构

```cpp
struct IpcMessage {
    MessageType type;       // 消息类型枚举
    std::string request_id; // 请求关联 ID（命令必填，事件可为空）
    int version = 1;        // 协议版本
    nlohmann::json payload; // 业务负载
    long long timestamp_ms; // 发送时间戳（事件必填）
};
```

### 3.3 MessageType 枚举

```cpp
enum class MessageType {
    // 命令（Python → 沙箱）
    Hello,           // 客户端握手，含 client_type
    StartProcess,
    WriteStdin,
    SignalProcess,
    TerminateProcess,
    QueryStatus,
    Shutdown,

    // 事件（沙箱 → Python）
    Ready,
    ProcessStarted,
    ProcessOutput,
    ProcessExited,
    ResourceLimitHit,
    AccessDenied,
    NetworkBlocked,
    BehaviorLog,
    StatsReport,
    CapabilityReport,
    Error,
    ShutdownComplete,

    // 控制
    Fragment,        // 分片消息
    Heartbeat,       // 心跳
};
```

### 3.4 ClientType

```cpp
enum class ClientType {
    Controller,  // 可发命令 + 收事件
    Observer,    // 仅收事件
};
```

## 4. 核心类与接口定义

### 4.1 IIpcServer（端口接口）

```cpp
// src/core/ports/IIpcServer.hpp
class IIpcServer {
public:
    virtual ~IIpcServer() = default;

    virtual Result<void> Start(const std::wstring& pipe_name) = 0;
    virtual Result<void> SendEvent(ClientId, const IpcMessage&) = 0;
    virtual Result<void> BroadcastEvent(const IpcMessage&) = 0;
    virtual void SetCommandHandler(ICommandHandler&) = 0;
    virtual Result<void> Shutdown() = 0;
    virtual std::vector<ClientInfo> ListClients() const = 0;
};
```

## 5. 详细流程图

### 5.1 客户端连接握手序列

```
Python                     NamedPipeServer           ICommandHandler
   │                              │                          │
   │── CreateFile(pipe) ─────────►│                          │
   │                              │── AcceptNamedPipe ──►   │
   │                              │   分配 ClientId          │
   │                              │←─ 启动 ClientReadLoop ──│
   │── Hello(client_type) ───────►│                          │
   │                              │── HandleCommand(Hello) ─►│
   │                              │←─ 返回 Ready 事件 ───────│
   │←── Ready 事件 ───────────────│                          │
   │   握手完成,可发命令/收事件    │                          │
```

### 5.2 命令处理序列

```
Python                     NamedPipeServer           UseCase
   │                              │                          │
   │── StartProcess(req) ────────►│                          │
   │                              │── DecodeFrame            │
   │                              │── HandleCommand ─────────►│
   │                              │                          │── StartProcessUseCase
   │←── ProcessStarted ───────────│←─ BroadcastEvent ────────│
   │←── ProcessOutput ────────────│←─ BroadcastEvent ────────│
   │←── ProcessExited ────────────│←─ BroadcastEvent ────────│
```

### 5.3 多客户端广播

```
Controller                 Observer A         Observer B
   │                            │                   │
   │── StartProcess ───────────►│                   │
   │←── ProcessStarted ─────────│                   │
   │                            │←── ProcessStarted │
   │                            │                   │←── ProcessStarted
```

### 5.4 异常断连处理

```
Python 崩溃               NamedPipeServer
   │   (连接断开)                │
   │                            │←── ReadFile 返回 ERROR_BROKEN_PIPE
   │                            │── 标记 disconnected = true
   │                            │── OnClientDisconnected 回调
   │                            │── 清理写队列 + Join 读线程
   │                            │── CloseHandle(pipe)
   │                            │   沙箱继续运行（无 controller 时按配置）
```

## 6. 错误处理与边界情况

### 6.1 错误码表

| ErrorCode | 含义 | 处理 |
|-----------|------|------|
| `IPC_INVALID_FRAME` | 帧长度非法或 JSON 解析失败 | 断开客户端 |
| `IPC_MESSAGE_TOO_LARGE` | 消息 > 16MB 且未分片 | 返回 Error |
| `IPC_UNKNOWN_MESSAGE_TYPE` | 未知 type 字段 | 返回 Error |
| `IPC_SCHEMA_VALIDATION_FAILED` | 字段缺失或类型错误 | 返回 Error |
| `IPC_CLIENT_NOT_AUTHORIZED` | observer 发命令 | 返回 Error |
| `IPC_PIPE_CREATE_FAILED` | CreateNamedPipeW 失败 | 启动失败 |
| `IPC_PIPE_CONNECT_FAILED` | ConnectNamedPipe 失败 | 重试或报错 |
| `IPC_WRITE_TIMEOUT` | 写操作超时 | 关闭该客户端 |

### 6.2 边界情况

| 情况 | 处理 |
|------|------|
| 客户端发送速度 > 服务端处理速度 | 写队列上限 1000 消息，超出丢弃 + 告警 |
| 客户端 ReadFile 阻塞 | OVERLAPPED 异步 + 超时 30s |
| JSON 解析失败 | 记录日志，断开客户端 |
| 分片消息未重组完成客户端断开 | 丢弃分片缓冲 |
| Shutdown 时仍有客户端连接 | 给 1s 优雅期，超时强制关闭 |
| 同一客户端重复 Hello | 拒绝第二个 Hello，返回 Error |
| controller 断开后无 controller | 按配置 `shutdown_on_no_controller`（默认 true） |

### 6.3 分片协议

```json
// 分片头（首片）
{
  "type": "Fragment",
  "payload": {
    "fragment_id": "uuid",
    "seq": 0,
    "total": 3,
    "original_type": "ProcessOutput",
    "data_base64": "..."
  }
}

// 后续分片
{
  "type": "Fragment",
  "payload": {
    "fragment_id": "uuid",
    "seq": 1,
    "total": 3,
    "data_base64": "..."
  }
}
```

接收方按 `fragment_id` 重组，收到全部 `total` 片后合并为完整消息。

## 7. 性能与资源估算

### 7.1 线程开销

| 组件 | 线程数 | 说明 |
|------|--------|------|
| AcceptLoop | 1 | 接受新连接 |
| ClientReadLoop | N | 每客户端 1 |
| ClientWriteLoop | N | 每客户端 1（或共享 1 个 + 队列） |

推荐：N 较小时（≤8）每客户端独立写线程；N 大时共享写线程池。

### 7.2 内存开销

| 组件 | 内存 |
|------|------|
| 每个 ClientSession | ~4KB（不含队列） |
| 写队列 | 每消息平均 1KB × 1000 上限 = ~1MB |
| 帧编解码缓冲 | 64KB |
| 总计（8 客户端） | ~10MB |

### 7.3 性能优化

- OVERLAPPED 异步 I/O，避免阻塞线程
- 写队列使用无锁队列（单生产者单消费者场景）
- 大消息分片时，分片间可插入其他事件（避免独占管道）
- 批量发送：多个小事件合并为一个 `BehaviorLog` 消息
