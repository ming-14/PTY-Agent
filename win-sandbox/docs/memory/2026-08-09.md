## Test 6 修复（同日）：ActiveProcessLimit 误杀 Job —— 真实产品 bug
- **结论**：间歇失败并非"测试竞态"，而是产品 bug。`StartProcessUseCase::OnNotification` 中
  `ActiveProcessLimit` 分支照搬 H-1/H-2 修复（commit 29099d7）调用了 `TerminateAllOnLimit()`。
- **根因**：H-1/H-2 的 `TerminateAllOnLimit` 只适用于 CPU/内存超限（Windows 只发通知不杀进程，
  进程继续违规运行）。**进程数超限语义完全不同**：Windows 在 CreateProcess 阶段直接拒绝超限
  进程入 Job（调用方侧 WinError 1816 / ERROR_NOT_ENOUGH_QUOTA），Job 内既有进程没有任何违规，
  TerminateAll 会误杀合法进程 → python 主进程在写完 FORK= 前死亡 → stdout 缺失间歇失败。
- **修复**：`ActiveProcessLimit` 分支只 `EmitResourceLimitHit`，不设 pending_exit_reason、不
  TerminateAll。验证：8/8 稳定 PASS，ctest 14/14 仍绿。
- 教训：Job 三类资源通知统一 TerminateAll 是过度抽象，进程上限是"创建时拒绝"类限制，与
  内存/CPU（运行期持续违规）机制本质不同。
